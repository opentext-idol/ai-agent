A metadata block maps logical field names to locations in the document's XML metadata. The same definition is used for both directions: reading input values before the lookup, and writing output values back after it.

path - the iteration scope

path is an XPath (relative to <xmlmetadata>) to the element the lookup operates on. Use "." for the document root. When path matches several elements (e.g. repeating <location> blocks) each match is enriched independently, using its own field values.

fields

Each entry of fields takes one of three forms:

  • Bare string - "latitude" is shorthand for { "name": "latitude", "path": "latitude" }; used when the logical name equals the element name.
  • Named leaf - { "name": "postcode", "path": "zip" } reads/writes the <zip> element but exposes it to the lookup as postcode.
  • Container - { "path": "address", "fields": [ ... ] } has no name; it descends a level so nested fields resolve relative to it.

Field paths are relative to the matched path element. A path may be a simple element name, a relative XPath (address/zip), an attribute (@country), self (.) or parent (..), or a property object { "property": "X", "default": "..." } that reads the path from a NiFi dynamic property at runtime. Output elements are created if they do not already exist.

value_element

Set value_element on a container (or the root) when the element will both carry a primary value as text and gain enriched child elements - which would otherwise be invalid mixed content. Before writing outputs, any existing text is migrated into a named child; a field with "path": "." then reads/writes that child. For example, an Eduction tag: 

Before:  <POSTAL_CODE>94143</POSTAL_CODE>

After:   <POSTAL_CODE>
           <postcode>94143</postcode>
           <latitude>37.7749</latitude>
           <longitude>-122.4194</longitude>
         </POSTAL_CODE>

is produced by a metadata root with "path": "POSTAL_CODE", "value_element": "postcode", and a field { "name": "postcode", "path": "." }.
