A csv_file describes a delimited data file that lookups can query. It does not contain the data - it points at a file (via file_key) and declares how to read it.

Locating the file

file_key is a key into a file_map block, which resolves to the actual file path. This indirection lets the file move without touching the data source or the lookups that use it.

Naming the columns

Lookups filter and read by logical column names. Those names come from one of:

  • use_header_row: true (the default) - the first row of the file is the header and supplies the column names.
  • headers: [ ... ] - an explicit list of names, used when the file has no header row (use_header_row: false).
  • names: [ ... ] - remaps or computes the logical names exposed to lookups. A bare string keeps a column as-is; an object { "name": ..., "expr": ... } exposes a computed value under a new name. Only columns listed in names are loaded when it is present, so it also acts as a column filter.

The separator defaults to ,; use "\t" for tab, or a hex escape (%XX / \xXX) for other delimiters.

Indexes

indexes lists sets of columns to index. A lookup whose inputs exactly cover an index resolves with a single index probe; without a matching index it scans the whole file. Create a single-column index for single-key lookups and a compound index for multi-key lookups.

Column typing

A logical column name beginning I_ or S_ is stored as integer or string respectively (the prefix is stripped from the stored name). A column named "-" is ignored.
